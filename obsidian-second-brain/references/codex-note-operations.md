# Note operations

Read this for an authorized capture, edit, or maintenance task. The current user's scope and the vault's applicable manual take precedence over bundled examples.

## Locate and classify

Search canonical notes by filename, title, aliases, and relevant terms before creating a new note. If results are sparse, try focused synonyms and routed folders. State the search scope before concluding something is absent; exhaustive scanning of unrelated or excluded folders is unnecessary.

Resolve the note type and destination from the route map, existing templates, and neighboring notes. For an existing routed vault, do not bootstrap a competing folder layout. When research or knowledge classification has a local contract, use it.

## Preserve meaning and sources

Match the vault's durable-note language, frontmatter, wikilinks, and human-facing style. Keep factual source URLs and enough attribution to trace claims. Separate event date, report date, and update date when the distinction matters. Mark uncertain or conflicting claims as such; an automatic reconciliation should not silently choose a winner.

Keep raw/source material immutable where required. Store the requested summary or interpretation in the appropriate derived note, with links to its source. Prefer a relevant excerpt and attribution over indiscriminate full-source copying.

## Apply scoped consistency updates

Update the existing destination when it represents the same entity or topic. Preserve unrelated content. For a new note, add useful existing links; do not create a stub for every incidental person or concept.

Use the vault's propagation table for changes directly caused by the task: for example, a completed task may require board, project, and daily-note consistency. The user's explicit only-file or read-only boundary remains controlling; report any related follow-up that falls outside it. A capture does not automatically authorize rewriting all related pages, importing all conversation content, or scheduling future maintenance.

Write operation records at the vault's routed location when the authorized write workflow requires them. An audit does not gain write permission merely because a legacy command says to log every operation.

## Verify and report

Inspect the diff or before/after text, confirm destination paths and frontmatter, and check newly introduced links against existing targets. For moves or merges, check inbound links and preserve history according to the vault's rules. Use available validators when relevant after inspecting their side effects; do not invoke a repair command merely to validate.

Report changed note links and unresolved source conflicts. Do not claim a scientific result, task completion, or external action solely from a plan, local note, or an older status entry.
