# Illustrated paper explanation

Identify the method's key inputs, transformations, outputs, and evaluation claim from the paper. Decide what each requested image needs to teach. Use visual analogies only when they preserve the relevant mechanism; distinguish analogy from an actual component of the method.

Reuse the user's specified language, number of images, audience, and style. Infer a small sensible scope when those choices are minor. Ask about a missing choice only when it changes the deliverable substantially; existing approval does not need to be repeated.

Select an available image-generation or diagram tool suited to the requested result. Respect a user-selected backend and the host's tool requirements. If the requested generation capability is unavailable, explain that limitation rather than presenting a different technique as the requested one. Do not install or configure a client merely to use this skill.

For a sequence, give each image a distinct explanatory purpose and keep terminology, symbols, and visual identity consistent. Check that arrows, ordering, labels, and comparisons match the paper. Do not invent experimental plots or numbers for visual effect.

Inspect every delivered image, correcting illegible labels, missing steps, or misleading mechanisms when possible. Provide the images or artifact the user requested and describe any remaining scientific or rendering uncertainty. Supporting notes and prompt files are optional unless needed for reproducibility or requested.
